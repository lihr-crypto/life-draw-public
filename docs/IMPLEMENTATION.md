# 第一版实施约定

本轮用户已授权开始实现。权威视觉：已接受的[字体与动效稿](design/accepted-motion-ui.png)，沿用方向 A 轻调版，暖白底 #FAF8F4、墨色 #292C2E、赤陶 #A34B39；信封盲抽、轻宋体，两张结果卡同等大小，分别轻微旋转和错位。只做每日新鲜事与灵感库，无底部 Tab。

## 交互

- 两个成员、两个独立身份，共享服务端持久状态。第一个创建空间，通过一次性邀请链接配对，用户自己复制链接，不自动对外发送。
- 每人一张，服务端抽取并占用；刷新不换签。抽取与等待响应不包含词，仅在双方抽好后揭晓本轮两张。
- 默认共同揭晓；暂不做两套可切换揭晓模式。等待可稍后继续，保留轮次。
- 首页已有未完成轮次显示“看看今天要做什么”，查看入口统一为“查看”；已揭晓后的说明不再显示。并发邀请冲突刷新后直接呈现回应入口，不重复显示待回应提示；其他失败仍保留说明。
- 两张初始不选中；本地点选不必同步。点击“就选这一张”创建邀请，对方点击“我也选这一张”后才共同选定。发起人可撤回，对方可拒绝，单人不能批准自己的邀请。
- 揭晓后的“重新抽取”先确认并邀请对方；双方同意后才换一组。需要至少两条其他可用灵感，排除当前两张，避免抽回原卡。不足时保留原卡和邀请并给出提示，可拒绝或撤回。成功时两张旧卡回池，新轮已盲抽两张但仍需“一起拆开”揭晓。
- 同一时刻仅一份选择或重抽邀请；双方竞争发起不会覆盖。每次发起带独立 proposalId，已处理邀请保留结果供重试，不允许旧回应改变新的邀请。
- 页面采用自托管 Noto Serif SC 400 字库。共同揭晓后播放封蜡松开、封口翻起、卡片浮出的约 1.8 秒过渡；选定后未选卡淡出、所选卡移到中央，最终 DOM 只保留一张。刷新或重新进入直接显示稳定状态，减少动态效果设置跳过动画。
- 选定进入待完成；点击“完成了”才记完成并移出可抽池。未选中的次日回池；取消明确确认，两张回池。
- 原词不改写。照片的 82 条作为备用素材导入，待核对文字和划线条目须明确核对后才允许加入抽签池。重复原词保留，重复来源 ID 的再次导入应幂等。
- 灵感库主动管理可看词；保密约束仅适用于抽签与揭晓过程。
- 可抽池和备用池每条内容均提供“编辑”和“删除”，编辑支持保存/取消并保留失败草稿；删除必须经用户确认后才提交，重复删除幂等。被本轮占用的条目禁止编辑或删除；服务端再次校验，不能依靠按钮禁用。
- 删除仅移除可抽池/灵感库条目及后续导出，既有轮次快照保留原文；已释放未选卡被删除后，所选卡仍可完成或取消，取消不会恢复被删除条目。
- 选定后的完成按钮为“完成了”，不再重复显示已共同选定的说明。灵感库页眉仅保留“灵感库”；可抽池/备用池条目的来源及备注仅在界面隐藏，数据和导出保留，待核对区仍展示必要核对信息。
- 备用池提供“批量启用”：勾选、全选、取消，仅将所选且无需核对的条目移到可抽池。失败保留选择；后台已移走或删除的条目不会再提交。服务端先完整校验全部ID、占用和确认状态，再统一写入，不允许部分启用或绕过核对。
- 可抽、备用、待核对和已完成栏目各自提供“收起/展开”，默认展开，收起后保留标题与数量。折叠仅影响展示；本次打开灵感库期间，列表同步或刷新不重置折叠状态，编辑草稿及批量勾选仍保留。
- 创建空间时可放入原创系统灵感的备用条目，但不自动启用。原照片、私有 JSON、运行数据库与 QA 身份资料不提交 Git。

## API（JSON，所有修改校验身份、成员资格与同源）

类型以 `app/contracts.ts` 为准。成功 mutation 返回最新 AppState（库修改返回 LibraryResponse）；错误为 `{ error: string, code: string }`，有意义的状态码。

- GET `/api/state`：当前状态，无成员返回 `space: null`。未揭晓时不得序列化 cards 或文字。
- POST `/api/space` `{name?:string}`：创建两人空间，第一个成员加入；已在空间内幂等返回。
- POST `/api/invite` `{}`：返回 `{token,expiresAt}`，同一空间仅一个有效一次性邀请，有效期 24h；配满后不可再邀请。
- POST `/api/join` `{token,name?:string}`：用邀请加入，拒绝第三人、过期、已用、自己邀请或已加入另一空间。
- GET `/api/library`：当前空间 LibraryResponse。
- POST `/api/library`：LibraryMutation。add/bulkAdd 的 activate 显式指定；import 全部先放备用区。needs_confirmation 或 needsUsageConfirmation 条目禁止 activate；edit 且 confirmReading 后解除待核对标记。held 条目不可编辑或移出。edit 不改变当前 active/reserve 状态；delete 载荷为 `{action:"delete",id}`，仅 active/reserve 且未占用条目可删，已删除 ID 重试成功返回最新库。
- POST `/api/draw` `{}`：同一人重复请求幂等；同一轮两个不同条目；不足两张或尚未配对明确报错。
- POST `/api/reveal` `{roundId}`：双方抽好后原子揭晓，同步状态。重复调用幂等。
- POST `/api/select` `{roundId,cardId,proposalId}`：创建选择邀请，不直接选定；缺少 proposalId 的旧载荷返回400。
- POST `/api/redraw` `{roundId,proposalId}`：创建重新抽取邀请；仅 revealed 可发起。
- POST `/api/respond` `{roundId,proposalId,action:"approve"|"decline"|"withdraw"}`：另一位成员可同意/拒绝，发起人可撤回。选择同意后原子选定；重抽同意后原子替换为 ready 新轮，隐藏所有词。批准原重抽的相同请求在换轮后重试仍返回最新状态，不会再次换轮。其他已过期或冲突操作返回409后刷新。
- `RoundView.proposal` 为 `{id,kind:"selection"|"redraw",requestedBy:"self"|"partner",cardId:string|null}` 或 null，不包含成员凭据。resolution/history 仅在服务端保存，不进入 AppState 或导出。
- POST `/api/complete` `{roundId}`：只有已选定可完成，重复幂等。
- POST `/api/cancel` `{roundId}`：释放本轮，已完成不可取消。
- GET `/api/export`：仅导出当前空间灵感数据，兼容重新导入；不含会话、配对 token 等凭据。

## 运行与授权边界

使用 Sites portable 本地工作流和 D1 持久数据库。本轮按 GitHub 工作流创建 PR，不新增站点、不合并或发布；现有站点的此前授权与状态见 HANDOFF.md。现有 Supabase 只是最初建议，当前版本无需配置付费外部服务。生产部署另行核对访问方式；保留 starter 的 Sites ChatGPT 身份辅助。若本地匿名设备身份用于 QA，只在 loopback 开发环境提供，生产必须使用平台可信身份。

## 检查

核心逻辑、隐私投影、无重复抽签、幂等、候选核对限制和共同确认需要行为测试；浏览器两独立上下文验证真实后端共享、冲突、重连与导入。390px及320px宽、长词、字号放大与减少动态效果需要界面检查。真机与远程上线不能用本地检查替代。
